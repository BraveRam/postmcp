## Automatic Environment Variable Resolution

When you invoke a preset via `postmcp run @<preset>`, PostMCP checks your shell environment for matching credentials automatically.

| Preset | Auth Type | Primary Env Variable | Fallback Env Variable |
| :--- | :--- | :--- | :--- |
| `@neon` | Bearer Token | `NEON_API_KEY` | `POSTMCP_API_KEY` |
| `@stripe` | Bearer Token | `STRIPE_SECRET_KEY` | `STRIPE_API_KEY` |
| `@github` | Bearer Token | `GITHUB_TOKEN` | `GH_TOKEN` |
| `@sentry` | Bearer Token | `SENTRY_AUTH_TOKEN` | `SENTRY_API_KEY` |
| `@supabase` | Header (`apikey`) | `SUPABASE_SERVICE_ROLE_KEY`| `SUPABASE_ANON_KEY` |
| `@resend` | Bearer Token | `RESEND_API_KEY` | `RESEND_TOKEN` |
| `@slack` | Bearer Token | `SLACK_BOT_TOKEN` | `SLACK_USER_TOKEN` |
| `@notion` | Header (`Authorization`) | `NOTION_API_KEY` | `NOTION_TOKEN` |
| `@cloudflare` | Bearer Token | `CLOUDFLARE_API_TOKEN` | `CF_API_TOKEN` |

## Overriding & Specifying Authentication Credentials

PostMCP supports four primary authentication mechanisms across presets and custom OpenAPI specifications:

### 1. Bearer Token Authentication
Pass a Bearer token directly on the CLI or expose `BEARER_TOKEN` in your environment:
```bash
# Pass via CLI flag
postmcp run @stripe --bearer "$STRIPE_SECRET_KEY"

# Or via environment variable
export BEARER_TOKEN="sk_live_..."
postmcp run @stripe
```

### 2. Custom Header or Query API Keys
Supply credentials formatted as `key=value`, `header:key=value`, or `query:key=value`:
```bash
# Header API key
postmcp run @neon --api-key "X-API-Key=secret123"

# Query parameter API key
postmcp run @weather --api-key "query:appid=secret123"

# Or via environment variable
export API_KEY="secret123"
postmcp run @neon
```

### 3. HTTP Basic Authentication
Send username and password credentials encoded as Base64 in the `Authorization: Basic ...` header:
```bash
# Pass username:password directly
postmcp run https://api.internal.corp/openapi.json --basic-auth "admin:supersecret"

# Pass an environment variable reference
postmcp run https://api.internal.corp/openapi.json --basic-auth "$INTERNAL_AUTH"

# Or via environment variable
export BASIC_AUTH="admin:supersecret"
postmcp run https://api.internal.corp/openapi.json
```

### 4. Direct Custom Headers (`-H`, `--header`)
Inject arbitrary custom headers for bespoke gateway requirements:
```bash
postmcp run @sentry -H "Authorization: Bearer $MY_SENTRY_KEY" -H "X-Client-Id: agent-1"
```

## Workspace Environment Persistence in Studio

When using the Visual Web Studio (`postmcp studio`), you can configure API keys via the **Workspace Credentials** modal. Keys entered in the Studio are securely persisted to your local machine (`~/.postmcp/workspace.json`) and never transmitted to external third-party servers.
